**Version:** 2.0 · Direction: *editorial trust console* — warm, considered, evidentiary. Anti-goal: "generic SaaS dashboard" / cold enterprise chrome / "hackathon dashboard."

## 1. Design Philosophy

1. **Trust is the interface.** Every AI decision must expose its reasoning in ≤ 2 clicks; every money-adjacent action shows impact, cost, and reversibility.
2. **Calm density.** Ops-grade information density (tables, chips, counters) with generous hierarchy — not marketing whitespace *inside the app*. (The public landing page is the one place whitespace is allowed to breathe — see §22.)
3. **Honesty badges.** Anything simulated/derived is visibly labeled `[SIMULATED]` — never hidden in tooltips.
4. **Deterministic chrome, AI accent.** The UI itself never feels generative; AI states are *marked*, not ambient.
5. **(v2.0 addition) Warmth is not weakness.** A cream/forest-green editorial palette with a serif display face is a *credibility* choice, not a decorative one — it reads as considered and human-reviewed rather than "AI-generated dashboard #4,000." The rigor (badges, hashes, CIs, kill switch) is what actually earns trust; the warmth is what gets someone to sit down and read it.

## 2. Brand / Visual Direction

**"A ledger you'd actually want to read."** A cream, faintly grid-papered canvas (like graph paper / an accountant's pad) carries the whole product — not a dark command-center bunker. One deep forest green ink does almost all of the "chrome" work (nav, primary buttons, headline text, one hero card per screen). Two accents are used *sparingly and on purpose*: a bright chartreuse/lime reserved for "the system is live and healthy" signals (never used as a data color), and a warm rust/terracotta used only for small tracked meta-labels, numbering, and the `[SIMULATED]` honesty badge. A single serif display face appears **once per screen** as the emotional/trust anchor headline — everything else is a clean grotesk sans. This supersedes v1.3's dual dark-navy/light-surface split: **there is now one light surface throughout** (cream page bg + white cards), with dark-forest used only for small, deliberate "featured" cards (Shield Status, the login left panel, the landing hero mockup) — never as a full-page background.

**Logo / wordmark:** small square/rounded-square mark (a simple leaf/spark glyph) in forest green (or lime on dark surfaces) immediately left of the wordmark "Reflex," set in the display serif at semibold.

**Reference screens (v2.0 source of truth):** `landing.jpg` (marketing hero + "One system, six guarantees"), `login.jpg` (split auth card), `dashboard-desktop.jpg`, `dashboard-mobile.jpg`.

**On reusing violet for both AI-content and `[TEST MODE]`:** v1.3 kept one violet strictly for AI-attributed elements and a separate indigo for the primary brand/Test-Mode. v2.0 has no indigo anymore (forest is primary), and the reference screenshots put `[TEST MODE]` in the same lavender family shown for one diagnosis chip. Rather than fight that, this doc reframes the hue's meaning slightly: **violet = "this is not deterministic ground truth"** — which covers both *LLM-generated* content and *synthetic Razorpay test-mode* data honestly. It is still the **only** use of that hue for anything, so §1.4 ("AI states are marked, not ambient") holds. `UNKNOWN_AMBIGUOUS` stays in the **stone** family exactly as v1.3 specified (its own "slate chip" rule) — it is not moved to violet.

Contrast: every text/background pairing above targets ≥ 4.5:1 (WCAG AA); this is a design target, not yet an automated gate — see §17.

## 4. Typography

- **Display (headlines only — one per screen/card, max):** `Fraunces` (var, opsz 72–144), weight 500–600, occasional italic 400 for the login-panel quote. Fallbacks: `Instrument Serif`, `Newsreader`, serif. **Rule: the serif appears exactly once as the emotional/trust anchor per screen** ("Recovery overview.", "Clarity for every failed payment.", "All clear.", "Recover more. / Annoy less. / Prove everything."). Panel/section titles ("Failures stream," "Shield status") are **not** serif — see next.
- **UI / body / panel titles / numbers:** `Inter` 400/500/600/700. **All monetary and numeric values** (counters, EV, %, table amounts): `font-variant-numeric: tabular-nums`, weight 700 — digits never shift width. This rule is unchanged from v1.3.
- **Tracked meta labels, table headers, IDs, hashes, timestamps:** `JetBrains Mono` 400/500, uppercase, `letter-spacing: 0.08–0.12em` for eyebrow labels (e.g. `AI REVENUE RECOVERY / 01`, `COMMAND CENTER`, `TUESDAY, 26 AUGUST 2026 / SIPDAILY`, table column headers). Acceptable substitute: `Inter` uppercase + wide tracking, if mono reads too "code-editor" in context.
- Scale (rem): 0.6875 (mono eyebrow) · 0.8125 (caption/table header) · 0.875 (body-small/buttons) · 1 (body) · 1.125 (panel title, Inter bold) · 1.75 (stat-card value) · 2–2.5 (serif card headline, e.g. "All clear.") · 3.25–4 (serif hero, landing page, clamp down on mobile).
- Indian currency grouping mandatory: `₹2,41,000` (util `formatINR`), paise→rupees client-side only. Unchanged from v1.3.

## 5. Background & Texture

- **App surfaces (dashboard, approvals, results, audit, ops):** flat `--cream`, no grid.
- **Auth + marketing surfaces (`/login`, `/` landing):** `--cream` with a faint grid-paper wash — 32–40px squares, 1px lines at `--stone-200` (or `rgba(22,38,29,0.05)`), full-bleed behind the centered card/hero. Never animate it; never let it run behind dense data tables (it competes with reading numbers).

## 6. Spacing

4px base grid: `4/8/12/16/20/24/32/40/48/64`. Card padding 24 (was 16 in v1.3 — the new cards are more generous); drawer padding 24; in-app section gap 32; marketing section gap 64; counter row gap 24.

## 7. Border Radius

- Buttons, badges/chips, mode selector, segmented control: **999 (full pill)** — every standalone button in the reference set is a stadium shape, no exceptions.
- Inputs / search fields: 10–12px.
- Standard cards (stat cards, content cards, table container): 16px.
- Feature/dark cards, hero mockup card, login split-card, drawers/modals: 20–24px.

## 8. Shadows

No more "dark surfaces = no shadow, borders only" split — the whole app is light now. **White cards on cream:** soft warm-tinted ambient shadow, `0 1px 2px rgba(22,38,29,.04), 0 8px 24px rgba(22,38,29,.06)`. **Elevated (login card, drawers/modals):** `0 24px 64px rgba(22,38,29,.12)`. **Forest/dark feature cards:** no shadow — separation comes from color contrast against cream, optionally a 1px inner top highlight `rgba(255,255,255,.06)`. Never glow effects on data.

## 10. Inputs

Fill style, not outline: `--stone-100` background, no visible border, radius 10–12px. Label always visible, **uppercase small-caps mono, above the field** (never placeholder-as-label) — matches the login screen's `EMAIL` / `PASSWORD` treatment. Helper text below in `--ink-muted`. Error text + icon (never color alone). Disabled shows reason tooltip. Guardrail inputs show current effective value vs proposed. Focus: 2px `--forest` ring, fill lightens to `--paper`.

## 12. Tables

Structure unchanged from v1.3 (sticky header, numeric right-aligned tabular, status = chip not text, row click = drawer, sortable, filter chips above, footer batch totals). **Reskin:** header row in mono-caps `--ink-muted` 13px; 1px `--stone-200` row separators (no zebra); row height 64px (generous, was implicit-dense in v1.3); primary cell = bold `--ink` name + muted mono ID below (e.g. `customer_amber` / `ep_01HZ4J9M8`); amount cell = bold tabular value + muted caption below (payment rail, e.g. `UPI_AUTOPAY`); diagnosis/state = pastel pill chips per §13; EV Score right-aligned, colored (`--success` positive / `--coral` negative, e.g. `-₹1.40`); row hover bg `--stone-100`.

## 13. Badges & Chips — Semantic Color System

**Two visual weights, used consistently:**
- **System/meta badges** (honesty labels): **outline** pill — 1px border in the hue, transparent/paper fill, text in the hue. Used for `[SIMULATED]`, `[TEST MODE]`.
- **Data/category chips** (diagnosis, state, action-status): **filled** pastel pill — bg + darker text in the same hue, per the family table in §3.

| Badge | Style |
|---|---|
| `[SIMULATED]` | `--rust` outline pill, mandatory on every simulated channel/datum/metric — never hidden in a tooltip |
| `[TEST MODE]` | `--violet` outline pill on Razorpay surfaces |
| `DEGRADED` | `--rust` **filled** solid pill on action rows & mode bar (filled, not outline — slightly more urgent than a passive `[SIMULATED]` tag) |
| Confidence chip | `--violet` family (AI-attributed); `< 0.6` auto-renders `UNKNOWN_AMBIGUOUS` in the **stone** family + tooltip "conservative default applied" — unchanged rule from v1.3, only the color name changed (slate → stone) |
| Caps (`2/4`, `1/2`) | `--stone` chip normally; `--coral` chip when at limit |

**Diagnosis chips — `canonical_code` → hue family** (filled pill):

| Family | Codes |
|---|---|
| `--rust` (in-progress / retriable) | `INSUFFICIENT_FUNDS`, `AUTH_DECLINED_SOFT`, `MANDATE_LIMIT_BREACH` |
| `--stone` (structurally blocked / needs customer action) | `EXPIRED_CARD`, `ISSUER_DOWNTIME`, `AUTH_DECLINED_HARD`, `MANDATE_REVOKED`, `INVALID_VPA`, `UNKNOWN_AMBIGUOUS` |
| `--teal` (customer-driven, calm) | `CUSTOMER_INITIATED` |
| `--violet` (flagged for review) | `RISK_HELD` |

| Family | States | Chip or plain text? |

**Outcome (`recovered`/`failed`/`expired`):** not chipped — rendered as bold colored text (`--success` / `--coral` / `--stone`) in EV/results contexts.

## 14. Alerts

Top banner strip (below control bar), reskinned: **Degraded** `--rust` filled banner "LLM unavailable — deterministic fallback active · actions stamped DEGRADED" · **Halted** `--coral` filled, non-dismissible, w/ resume CTA (Primary/forest button so the CTA doesn't fight the alert color) · **Budget low** `--rust` filled (>80% daily budget). ## 16. Trust / Financial-Action UI (mandatory pattern)

Every action surfaced to a human shows the **Action Preview Card**:

```text
┌──────────────────────────────────────────────┐
│ WHAT    Send WhatsApp payment-link nudge [SIMULATED] │
│ WHY     INSUFFICIENT_FUNDS · salary-window retry     │
│ IMPACT  ₹299 recovery · cost ₹0.80 · EV +₹98         │
│ RISK    Annoyance penalty ₹22 · contact 2 of 2 today │
│ GATE    Shield PASS · policy v2 · quiet-hours clear  │
│ APPROVAL Not required (<₹50,000)                     │
│ REVERSIBILITY  Message only — cannot move money;     │
│                stop = suppression (instant)          │
└──────────────────────────────────────────────┘
```

Rules unchanged from v1.3: WHAT/WHY/IMPACT/RISK/GATE/APPROVAL/REVERSIBILITY always present · amounts never inside prose (own row) · irreversible-class actions (none in MVP) would require typed confirmation. **Visual skin (v2.0):** card = `--paper`, radius 16, row labels in mono-caps `--ink-muted`; amounts Inter tabular bold; the inline `[SIMULATED]` tag uses the §13 outline-rust badge style.

## 17. Responsive Design

- **Desktop ≥1280:** primary demo target — full density, drawers 480px.
- **Tablet 768–1279:** counters wrap 2×2; stream single-column; drawers full-width sheets.
- **Mobile <768:** view-focused monitoring (counters + stream), approve/decline as the single supported mutation; `/ops` controls hidden. **v2.0 confirms this pattern in the reference mobile capture:** top bar collapses to logo + Kill switch only, `MODE: ADVISORY` drops to its own row, all cards go full-width single column in the same order as desktop top-to-bottom, no information is dropped — only re-flowed.

## 18. Accessibility

WCAG 2.1 AA: contrast ratios designed ≥ 4.5:1 — **this is now a bigger open item than in v1.3**, since the new palette leans on mid-tone pastels; run an automated contrast pass before demo day, especially on `--rust`/`--teal` chip text-on-fill pairs. Full keyboard nav (roving tabindex on stream; ⌘K command palette: approve next / kill switch) · focus traps in drawers · `aria-live="polite"` on counters (assertive on Degraded/Halted) · chips carry icon + text where possible (never color-only — the plain-text terminal states in §13 lean on wording, e.g. "stopped low ev," precisely so color isn't the only signal) · reduced-motion honored · ledger rows have accessible names incl. hash.

## 19. Animation / Motion

150–200ms ease-out only. Counter ticks: 300ms odometer roll. Stream cards: slide-in 4px. Banner: slide-down. **No** pulsing AI orbs, no parallax, **no animating the background grid** (§5). `prefers-reduced-motion` disables all except banner.

## 20. Empty States

Each with: icon, one-line state, primary CTA. Unchanged from v1.3:
- No failures yet: "No failed payments in window. Start a replay to see Reflex work." → `[Start demo slice]`
- No approvals: "Queue is clear — nothing is waiting on a human."
- No eval results: "No evaluation runs yet. `./eval/reproduce.sh` or press Run — protocol pre-registered."
- Suppression list empty / ledger empty variants.

## 21. Loading States

Skeletons (structure-matched, no spinners) ≤ 400ms; then content. SSE reconnect: stale-data toast "Reconnecting… data may lag" + last-event timestamp. LLM diagnosis in-flight: per-episode 3-step progress (§15).

## 22. Error States

Inline where possible · toast (5s) for transient · full-page only for auth/major outage (with retry + status link) · API errors map to human text ("Razorpay test API timed out — action parked, will retry") · every error state names the recovery path · errors never hide `[SIMULATED]`/`[TEST MODE]` context.

## 24. Frontend Implementation Status (v2.0 — reset for the new visual layer)

**This section is intentionally reset.** The v1.1 implementation table from v1.3 recorded real, tested work — but it was tested against the old indigo/dark-navy tokens, which no longer exist as of this doc. Two different things are true at once:

1. **Structural/behavioral code is reusable, not thrown away.** Routing, the 21 source files, `tsc`/`vite build`/vitest passing, RBAC, drawer focus-trap logic, SSE hooks, `formatINR`, the Action Preview Card's WHAT/WHY/IMPACT/… structure, screen inventory, accessibility attributes (`aria-live`, roving tabindex, reduced-motion) — none of that depended on the color palette. It should survive a re-skin untouched.
2. **The visual layer itself is [NOT YET IMPLEMENTED] against v2.0** — nothing in `apps/web` currently reflects §2–§13 of this doc. A re-skin pass needs to touch, specifically: `tailwind.config.ts` (full token replacement per §3/§6/§7/§8), global font imports (Fraunces + Inter + JetBrains Mono via `@font-face`/Google Fonts), the badge/chip components (§13's outline-vs-filled split + the enum→hue mapping tables), button components (§9, incl. new Segmented Control and Mode Selector), card components (§11's five variants), table row styling (§12), the login page markup (new split-card layout), and — new — a `/` landing route that did not exist in v1.3's scope at all.

Until a re-skin pass runs, treat every visual claim as `[NOT IMPLEMENTED]` and every behavioral claim from the old §23.1/§23.2/§23.3 as still substantively true, just wearing the wrong colors.
