# Design — Reflex UI/UX & Design System

**Version:** 1.1 · Direction: production-grade fintech ops console — calm, dense, trustworthy. Anti-goal: "hackathon dashboard."

## 1. Design Philosophy

1. **Trust is the interface.** Every AI decision must expose its reasoning in ≤ 2 clicks; every money-adjacent action shows impact, cost, and reversibility.
2. **Calm density.** Ops-grade information density (tables, chips, counters) with generous hierarchy — not marketing whitespace.
3. **Honesty badges.** Anything simulated/derived is visibly labeled `[SIMULATED]` — never hidden in tooltips.
4. **Deterministic chrome, AI accent.** The UI itself never feels generative; AI states are *marked*, not ambient.

## 2. Brand / Visual Direction

"Mission control for leaking revenue." Dark-navy command surfaces for the live stream; light surfaces for results/audit (print-like evidence). One violet AI accent used *only* on AI-attributed elements. Rounded-but-restrained (8–12px), crisp 1px borders over shadows.

## 4. Typography

- **UI:** Inter (400/500/600/700). **Numbers (counters, amounts, EV):** `font-variant-numeric: tabular-nums`, weight 700 — digits never shift width.
- **Ledger/IDs/code:** JetBrains Mono 400/500.
- Scale (rem): 12 (caption) · 13 (meta) · 14 (body) · 16 (emphasis) · 20 (section) · 28 (card title) · **40/56 (hero counters)**.
- Indian currency grouping mandatory: `₹2,41,000` (util `formatINR`), paise→rupees client-side only.

## 5. Spacing

4px base grid: `4/8/12/16/24/32/48`. Card padding 16; drawer padding 24; section gap 32; counter row gap 24.

## 6. Border Radius

Chips/badges 999 (pill) · buttons/inputs 8 · cards 12 · drawers/modals 16 (top corners only) · tables 12 (outer).

## 7. Shadows

Dark surfaces: none — 1px `#223052` borders + subtle top-highlight. Light surfaces: `sm` (cards) `0 1px 2px rgba(15,23,42,.08)`, `lg` (drawers) `0 24px 48px rgba(15,23,42,.16)`. Never glow effects on data.

## 8. Buttons

| Variant | Usage | Rules |
|---|---|---|
| Primary | Enable agent, Approve | Indigo; disabled ≠ loading (spinner state) |
| Destructive | **Kill switch**, Decline | Red outline → solid on confirm-modal |
| Ghost | Drawer actions, filters | Borderless, hover bg |
| AI-action | "Regenerate reasoning" | Violet outline only |

All: height 36 (sm 28), 12px h-padding, focus ring 2px offset 2px, min touch 44px on mobile.

## 9. Inputs

Label always visible (no placeholder-as-label) · helper text · inline validation (amounts in ₹ with paise rounding hint) · error text + icon (never color alone) · disabled shows reason tooltip · guardrail inputs show current effective value vs proposed.

## 10. Cards

**Episode card:** left rail = status color · title `₹299 · UPI · #4821` · diagnosis chip + confidence · action status chips · age ("4h 12m old") · right: last EV delta. **Counter card:** label (12 muted) · value (40–56 tabular) · delta vs baseline w/ arrow · sparkline. Hover: raise border to `--primary`; click opens drawer.

## 11. Tables

Sticky header · zebra off, 1px row separators · numeric right-aligned tabular · status = chip not text · row click = drawer · sortable (amount, age, EV) · filter chips above · footer: batch totals. Used in: approvals, results, audit, episodes list view.

## 12. Badges

| Badge | Style |
|---|---|
| Diagnosis chips | `RULE` = neutral slate; `LLM` = violet w/ confidence (e.g., `LLM · 0.87`) |
| Status | state colors (AppFlow §14) |
| `[SIMULATED]` | amber-outline pill, mandatory on every simulated channel/datum/metric |
| `[TEST MODE]` | indigo-outline pill on Razorpay surfaces |
| `DEGRADED` | amber solid on action rows & mode bar |
| Caps | `2/4`, `1/2` counter chips (red when at limit) |

## 13. Alerts

Top banner strip (below control bar): **Degraded** amber "LLM unavailable — deterministic fallback active · actions stamped DEGRADED" · **Halted** red w/ resume CTA · **Budget low** amber (>80% daily budget). Banner = dismissible never for Halted; every banner event ledgered.

## 14. AI-Specific UI

| Pattern | Spec |
|---|---|
| **AI reasoning state** | During diagnosis: 3-step progress (ingest → classify → verify) with per-step check; never a generic spinner |
| **Confidence** | 0–1 chip; < 0.6 auto-rendered `UNKNOWN_AMBIGUOUS` slate chip + tooltip "conservative default applied" |
| **Recommendation (EV drawer)** | Header violet `AI-ranked action` · formula rendered with live numbers: `EV +₹98 = p 0.34 × ₹299 − ₹0.8 − ₹22` · four terms each hoverable w/ plain-language explainer · runner-up candidates listed with their EVs |
| **Action preview** | Exact message text (post-injection) + channel + cost + "no money moves in this action" note |
| **Approval state** | Card shows countdown, approver-required role, approve/decline + reason input |
| **Audit trail (ledger drawer)** | vertical timeline, mono font, per-event hash (truncated), `mode` stamps, blocked actions included with BLOCK reason |
| **AI uncertainty** | UNKNOWN chips, low-confidence tooltips, "regenerate" (violet) only where safe (diagnosis rationale view) |

## 15. Trust / Financial-Action UI (mandatory pattern)

Every action surfaced to a human shows the **Action Preview Card**:

```text
┌──────────────────────────────────────────────┐
│ WHAT    Send WhatsApp payment-link nudge [SIMULATED] │
│ WHY     INSUFFICIENT_FUNDS · salary-window retry     │
│ IMPACT  ₹299 recovery · cost ₹0.80 · EV +₹98         │
│ RISK    Annoyance penalty ₹22 · contact 2 of 2 today │
│ GATE    Shield PASS · policy v2 · quiet-hours clear  │
│ APPROVAL Not required (<₹50,000)                     │
│ REVERSIBILITY  Message only — cannot move money;     │
│                stop = suppression (instant)          │
└──────────────────────────────────────────────┘
```

Rules: WHAT/WHY/IMPACT/RISK/GATE/APPROVAL/REVERSIBILITY always present · amounts never inside prose (own row) · irreversible-class actions (none in MVP) would require typed confirmation — pattern documented for `[PLANNED]` features.

## 16. Responsive Design

- **Desktop ≥1280:** primary demo target — full density, drawers 480px.
- **Tablet 768–1279:** counters wrap 2×2; stream single-column; drawers full-width sheets.
- **Mobile <768:** read-only monitoring (counters + stream + approvals approve/decline); `/ops` controls hidden (server enforces anyway); demo is desktop-first — mobile is a courtesy, not a showcase.

## 17. Accessibility

WCAG 2.1 AA: contrast ratios tested · full keyboard nav (roving tabindex on stream; ⌘K command palette: approve next / kill switch) · focus traps in drawers · `aria-live="polite"` on counters (assertive on Degraded/Halted) · chips carry icon + text (never color-only) · reduced-motion honored · ledger rows have accessible names incl. hash.

## 18. Animation / Motion

150–200ms ease-out only. Counter ticks: 300ms odometer roll. Stream cards: slide-in 4px. Banner: slide-down. **No** pulsing AI orbs, no parallax. `prefers-reduced-motion` disables all except banner.

## 19. Empty States

Each with: icon, one-line state, primary CTA.
- No failures yet: "No failed payments in window. Start a replay to see Reflex work." → `[Start demo slice]`
- No approvals: "Queue is clear — nothing is waiting on a human."
- No eval results: "No evaluation runs yet. `./eval/reproduce.sh` or press Run — protocol pre-registered." 
- Suppression list empty / ledger empty variants.

## 20. Loading States

Skeletons (structure-matched, no spinners) ≤ 400ms; then content. SSE reconnect: stale-data toast "Reconnecting… data may lag" + last-event timestamp. LLM diagnosis in-flight: per-episode 3-step progress (Design §14).

## 21. Error States

Inline where possible · toast (5s) for transient · full-page only for auth/major outage (with retry + status link) · API errors map to human text ("Razorpay test API timed out — action parked, will retry") · every error state names the recovery path (AppFlow §11) · errors never hide `[SIMULATED]`/`[TEST MODE]` context.
