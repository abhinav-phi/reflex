# Reflex — AI Revenue Recovery Agent (Razorpay AI Buildathon, Track 03)

> Reflex is a bounded, root-cause-diagnosing payment-recovery agent: it ingests failed-payment
> webhooks, diagnoses each failure's root cause (rules first, LLM only for an ambiguous tail),
> ranks candidate interventions by expected value, enforces non-overridable deterministic
> guardrails, recovers via Razorpay TEST-MODE payment links, and writes every action to a
> hash-chained ledger. Tagline: "Recover more, annoy less, prove everything." Governing
> principle: "AI proposes, deterministic code disposes." Official pre-registered evaluation
> [SIMULATED]: Reflex recovered **31.27% [95% CI 28.91–33.9]** of failed value vs **21.22%**
> for a tuned-naive baseline and 4.68% organic — incremental **+10.05 pp [+7.68, +12.56]**,
> at ₹0.27 cost per ₹100 recovered and 0.256% complaint rate.

## What this project is

Failed recurring payments in India (UPI/card/mandate auto-debits) fail for many different root
causes — insufficient funds near salary day, issuer downtime, expired cards, revoked mandates —
and generic retry-and-spam recovery ignores those causes, wasting money and annoying customers.
Reflex's thesis: most failed-payment revenue doesn't need a better retry button, it needs a
correct diagnosis followed by a bounded, cheapest-appropriate action. An LLM is used only where
its strength lies (classifying messy, ambiguous bank-decline text); every decision that touches
money or customers is made by deterministic, auditable code. The entire system is evaluated by a
pre-registered protocol whose hidden simulation parameters are structurally invisible to the
agent (database role separation).

## Critical honesty context (read first)

- Everything measured is **[SIMULATED]** — synthetic customers, simulated channels, Razorpay
  TEST MODE only. No real money moved, no real customers contacted, ever.
- Pre-registered design targets were ~42% / ~24% / ~7% recovery (Reflex/naive/organic). Measured
  actuals are **31.27% / 21.22% / 4.68%**. The G1 gate (≥ +15 pp incremental over naive) was
  **MISSED at +10.05 pp [+7.68, +12.56]** and is reported verbatim — never tuned away.
- The CI excludes zero, so the effect is real; it is smaller than the aspirational target.
- **Two runs, reported honestly:** the official citable run (`eval/results/20260826T105147Z/`)
  executed **WITHOUT a key** — the reflex arm is the rules-first path end-to-end. The
  **Amendment-2 keyed rerun** (2026-08-26; `x-preview-f-free`, temperature 0, valid parses
  confirmed) measured the LLM tail at **zero delta**: the model honestly classified every
  synthetic ambiguous-tail string as UNKNOWN_AMBIGUOUS — matching the conservative fallback.
  Safety proven under real provider conditions; differentiation requires real-world decline
  strings. Full honest record: `docs/limitations.md`.

## Architecture

Six subsystems, one deployable unit:

- **Pulse** — webhook ingestion: HMAC verification, provider-event-id dedup, episode creation;
  rules-first diagnosis (regex/lookup covers ~89.6% of a 500-case holdout) with an LLM tail for
  the ambiguous remainder.
- **Brain** — EV policy: `EV = p_recover × amount − channel_cost − annoyance_penalty`; all four
  terms persisted per candidate intervention; v1 logistic priors frozen; v2 trainer written.
- **Shield** — deterministic, fail-closed guardrails: max 4 actions/episode, 2 contacts/customer/
  day, ₹5,000/day spend budget, quiet hours 21:00–09:00 IST, suppression/DND lists, human
  approval required above ₹50,000, global kill switch (drain of 500 scheduled actions measured
  at 25.5 ms [LOCAL RUN]).
- **Hands** — Razorpay TEST MODE adapters (orders, payment links) plus explicitly labeled
  [SIMULATED] channel simulators (WhatsApp/SMS/email/voice). Rejects any non-`rzp_test_` key
  (`TestModeViolation`). Duplicate payment-link guard: reference-id lookup before create and
  after timeouts.
- **Ledger** — append-only hash-chained action log: `sha256(seq ‖ prev_hash ‖ canonical(event))`,
  tamper-detection endpoint, app DB role limited to INSERT/SELECT.
- **Proof** — replay engine, hidden-parameter outcome simulator, honestly tuned baselines, and
  the pre-registered evaluation harness (`eval/PROTOCOL.md`).

AI components: **AI-1** diagnosis NLU (rules + LLM tail), **AI-2** EV policy, **AI-3** message
generation (slot-skeleton phrasing; validator rejects any digit/URL/₹/UPI token AND spelled-out
number words in Hinglish or English; template fallback on violation), **AI-4** reply classifier
(PROMISE/REFUSE/COMPLAINT/OPTOUT/PAYING/AMBIGUOUS; keyword gate first; sarcasm/negative-polarity
gate before LLM acceptance; COMPLAINT precision ≥95% and recall ≥90% gates green offline).

## Anti-cheat architecture

Postgres role separation makes rigging structurally difficult: the agent role (`reflex_agent`)
physically cannot SELECT the hidden simulator tables (`replay.sim_customers`, `replay.sim_events`) —
verified by SQLSTATE-42501 tests. The evaluation protocol was committed and git-tagged
(`eval-preregistered-v1`, plus amendments) BEFORE any results existed. Baseline B1 is honestly
tuned (documented grid search in `eval/results/b1_tuning.json`). A losing cohort is published.
Reproduction is proven: two complete independent official runs on different days produced
byte-identical per-seed results.

## Measured results (official pre-registered run, ALL [SIMULATED])

Protocol `eval-preregistered-v1` (Amendment 2: deterministic eval clock; the keyed LLM-tail
rerun is described in `docs/limitations.md` §3b), N=3,000 episodes × seeds {42, 1337, 2025} ×
8 arms, bootstrap 95% CIs (1,000 episode-level resamples). Artifacts:
`eval/results/20260826T105147Z/`.

| Arm | Recovery % [95% CI] | Cost / ₹100 | Complaints | Median TTR |
|---|---|---|---|---|
| B0 do-nothing | 4.68 [3.71, 5.75] | — | 0% | 35.7 h |
| B1 tuned naive | 21.22 [19.10, 23.36] | ₹0.15 | 0.478% | 5.0 h |
| **Reflex** | **31.27 [28.94, 33.98]** | **₹0.27** | **0.256%** | **10.3 h** |

- Incremental recovery vs B1: **+10.05 pp [+7.83, +12.62]** (CI excludes zero).
- Gate scorecard: G2 cost ≤ ₹3.5 **PASS** · G3 complaints < 0.5% **PASS** · G5 same-seed
  reproduction **PASS (proven)** · **G1 ≥ +15 pp MISSED at +10.05 pp — reported honestly** ·
  G6 vacuous without LLM differentiation.
- Per-seed Reflex recovery: seed 42 → 33.83%, seed 1337 → 29.39%, seed 2025 → 30.52%.
- Reproducibility proof: two complete independent runs on different days
  (`eval/results/20260825T221826Z/` and `eval/results/20260826T105147Z/`) produced
  byte-identical per-seed results across all arms (G5 PASS).
- Ablations: A1 rules-only 31.27% (= full; the LLM conservatively agrees with the fallback on
  the synthetic ambiguous tail — see limitations §3b) · **A2 EV-off 36.35% [33.89, 38.99]** —
  higher recovery at ~2.1× the cost (₹0.57 vs ₹0.27 per ₹100) and ~2× the complaints
  (0.522% vs 0.256%), committed as an honest negative result
  (over-pessimistic v1 priors; remedy is protocol-disciplined v2 recalibration) · A3 static
  templates 31.27% · **A4 no-timing 25.55% [23.54, 28.07]** ⇒ salary-cycle timing is the
  strongest measured lever (≈ +5.7 pp) · DEGRADED 31.27%.
- Losing cohort: 3,526 episodes where Reflex correctly DECLINED to act (contact cost > expected
  value); B1 spends on all of them at 1.9× Reflex's complaint rate.

## Quickstart

```
git clone https://github.com/abhinav-phi/reflex.git && cd reflex
cp .env.example .env        # optional: add LLM_API_KEY (system runs LLM-absent-safe without it)
make up                     # docker compose: postgres(15432)+redis+api+workers+web + migrations
make seed                   # idempotent: 4 users, merchant "SipDaily", policy v1, corpora
make demo                   # 214 episodes / ₹2,41,000 failed value, seed demo-7, ×100 speed
```

- UI: http://localhost:8080 (Docker) or http://localhost:5173 (dev). API: :8899 (dev) /
  :8000 (Docker). Postgres host port: 15432 (Windows reserves port ranges covering 5432).
- Seeded logins (password `reflex-demo`): admin@reflex.dev · operator@reflex.dev ·
  approver@reflex.dev · viewer@reflex.dev.
- Official evaluation: `./eval/reproduce.sh` (refuses to run if the pre-registration tag is
  missing). Backend tests: `make test` (164 passing [LOCAL RUN]; CI backend job green).

## Known limitations (summary)

- G1 (incremental ≥ +15 pp) MISSED at +10.05 pp — real effect, smaller than target.
- LLM-tail recovery value unmeasured on synthetic data: an honest model matches the
  conservative fallback on deliberately-unclassifiable strings (§3b of limitations).
- A2 EV-off anomaly (36.35% > 31.27%) pending v2 prior recalibration.
- Same-seed reproduction drift existed pre-TASK-061; fixed and re-proven (see G5 above).
- Live Razorpay test-mode observation of the duplicate-payment-link guard still owed.
- Live deployment exists (Vercel UI + Railway API, [SIMULATED] data); real-key LLM tail
  differentiation and a produced pitch video still pending.

## Non-goals

Real customer contact; irreversible money movement; replacing gateway retry logic; live API
keys anywhere in the evaluation path; auto-retraining without a fresh pre-registration.
